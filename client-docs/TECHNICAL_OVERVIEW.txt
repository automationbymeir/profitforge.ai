ProfitForge – Phase 1 Technical Overview AI-Ready Product Data
Extraction Pipeline (Revised Scope)

Purpose Phase 1 delivers a focused, production-ready pipeline for
extracting structured product data from vendor PDFs and objectively
measuring mapping accuracy. The emphasis is on deterministic validation,
repeatable benchmarking, and iterative model improvement rather than
building a full platform or admin system.

This phase is intentionally minimal and engineering-oriented: validate
accuracy first, then expand scope.

Core Principle • PDF is the only input format • XLSX is NOT generated by
the AI • XLSX serves only as a manually vetted ground-truth benchmark •
All model quality is measured against this benchmark

System Architecture (Phase 1) PDF Intake → OCR/Table Extraction → AI
Field Mapping → Benchmark Comparison → Accuracy Score

Components

1.  PDF Intake

-   Upload endpoint for vendor PDF catalogs
-   Stored in Azure Blob Storage
-   File validation (type/size)
-   No multi-format ingestion in this phase

2.  Extraction Pipeline

-   Azure Document Intelligence (OCR + table detection)
-   Multi-page support
-   Structured raw outputs retained for analysis/debugging
-   Produces normalized table data

3.  AI Mapping Engine

-   LLM-based mapping (Claude/OpenAI)
-   Maps extracted fields → target product schema
-   Confidence scoring per field
-   Prompt + model configurable
-   Supports rapid reruns without code changes

4.  Lightweight Review UI

-   Minimal HTML/React interface
-   Upload files
-   Trigger runs
-   Inspect outputs
-   No admin portal or complex workflows

5.  Golden Dataset & Benchmark Framework

-   Manually created PDF ↔ XLSX pairs
-   XLSX represents expected output
-   Deterministic comparison against ground truth
-   Produces objective accuracy metrics
-   Used in both development and production

Benchmark Usage

Development: - Internal tuning of prompts/models - Measure improvements
across iterations

Production: - Optional validation for new vendors or model changes - Run
AI output vs manually vetted XLSX - Generate grade - Decide if accuracy
meets threshold

Note: This is not required for every file. It is used periodically to
maintain confidence and calibrate performance.

6.  Iterative AI Optimization

-   Modify prompt or model
-   Rerun mapping
-   Regrade
-   Backtest against historical benchmarks
-   No redeploy required

Goal: continuous improvement without rewriting code or rebuilding
infrastructure.

Out of Scope (Phase 1) - Full admin portal - Data Factory
orchestration - Vendor memory/templates - Multi-format intake
(XLSX/CSV/etc) - Security/compliance ownership - Alternative OCR engines

Deliverables - PDF intake pipeline (Blob Storage) - Document
Intelligence extraction integration - LLM mapping engine with confidence
scoring - Simple UI for execution/review - Golden dataset (≥10 validated
PDF↔XLSX pairs) - Deterministic grading framework - Prompt/model tuning
capability - Accuracy metrics report - Source code + deployment
documentation

Operational Workflow (Practical) 1. Upload vendor PDF 2. Run
extraction + mapping 3. Review output 4. (Optional) Create one manually
vetted XLSX for validation 5. Grade accuracy 6. Tune prompt/model if
required 7. Re-run and validate 8. Move to automated processing

Performance Target - Objective measurable accuracy - Target baseline: ≥
85% on benchmark set

Future Phases - XLSX and other input formats - Alternative OCR engines -
Vendor format memory/templates - Full portal and workflow automation -
Expanded orchestration

Summary Phase 1 provides deterministic, benchmark-driven extraction
accuracy with configurable AI mapping and rapid iteration, while
intentionally avoiding heavy platform features until reliability is
proven.
